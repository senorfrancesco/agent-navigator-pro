# Dependency Audit 2026-04-12

## Scope

Аудит охватывает Python-зависимости из `backend/requirements.txt`, `requirements.chainlit.txt` и offline lock-файлов в `deploy/offline_bundle/`.
`package.json` не включён в таблицу, потому что пользователь просил сверку `requirements`, а для `npm`-зависимостей нужен отдельный аудит по `npm`/`pnpm`-регистру.
Колонка `PyPI` заполнена точечно для ключевых библиотек и для мест, где нужно проверить расхождение между каталогами.

## Key Findings

- Минимальные версии в `backend/requirements.txt` и `requirements.chainlit.txt` системно отстают от уже используемой среды и от offline lock-файлов.
- Текущая локальная среда уже поднята существенно выше старых floor-ограничений: особенно по `LangChain`, `LangGraph`, `FastAPI`, `Chainlit`, `transformers`, `torch`, `numpy`, `pandas`.
- Будущий PR на dependency refresh нельзя смешивать с текущим большим ребрендингом и другими несвязанными изменениями. Его нужно делать отдельной чистой веткой после стабилизации рабочего дерева.
- Для части библиотек достаточно поднять floor-версии до уже проверенных значений из текущей среды или offline lock. Для экосистем `LangChain`/`LangGraph`, `FastAPI`/`Starlette`/`Pydantic`, `Chainlit`, ML-стека и `ONNX` нужен отдельный совместимый прогон.

## Context7 Notes

- `FastAPI`: актуальная документация завязана на современный стек `Starlette` + `Pydantic`; поддержка `pydantic.v1` обозначена как устаревающая, поэтому обновление `FastAPI` нужно вести вместе с контролем связки `Pydantic` и `Starlette`.
- `LangChain`: текущая документация уже описывает современную агентную линию, а для старых цепочек отдельно упоминается `langchain-classic`. Это прямой сигнал, что переход с ранних `0.x` floor-ограничений в `requirements` надо рассматривать как осознанную миграцию.
- `Chainlit`: документация и текущий каталог уже находятся в линии `2.x`; старые миграционные заметки для `1.x` подчёркивают, что апгрейд затрагивает runtime defaults и контейнерный запуск.

## Recommended PR Shape

1. Низкий риск: поднять устаревшие минимальные версии утилит и клиентских библиотек до уже используемых значений, не меняя архитектуру.
2. Средний риск: отдельно проверить runtime/UI-зависимости и документный стек (`FastAPI` периферия, `uvicorn`, `httpx`, `llama-cpp-python`, `WeasyPrint`, `pymupdf`).
3. Высокий риск: отдельным slice обновлять `LangChain`/`LangGraph`, `Chainlit`, ML-стек (`transformers`, `sentence-transformers`, `torch`, `numpy`), `ONNX`-цепочку и `Qdrant`.

## Immediate Recommendation

- Не делать массовый апдейт зависимостей в текущем грязном дереве.
- После стабилизации разработки открыть отдельную ветку и обновить сначала сами `requirements`/lock-файлы, затем прогнать таргетные `pytest`, `python -m py_compile`, `bash -n` и smoke-проверки `Open WebUI` / `Chainlit`.
- Для `torch`, `onnx`, `transformers`, `sentence-transformers`, `qdrant-client`, `langchain*`, `fastapi` и `chainlit` закладывать отдельный regression pass, а не только mechanical bump версий.

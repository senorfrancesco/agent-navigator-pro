## 1. Решения, которые уже зафиксированы

- [x] Остаёмся на `Open WebUI`, не уходим на другую платформу.
- [x] Базируемся на `v0.8.12`, а не на `dev`.
- [x] Делаем форк `Open WebUI`, а не наращиваем `legacy_patch`.
- [x] `tool_jobs` остаётся единственным источником истины для долгих задач.
- [x] `qdrant` не используется для состояния `deep-job`.
- [x] `open_webui:deep_job` используется только как якорь в `assistant-message`.
- [x] Пользовательский класс панели фиксируется как `Инструмент долгого выполнения`, а имя конкретного инструмента отображается отдельно.
- [x] Панель не зависит напрямую от сырых событий `LangGraph` или `LangChain`; UI читает только нормализованный execution-контракт поверх `tool_jobs`.
- [x] Если workflow использует `LangGraph` или `LangChain`, их события сначала переводятся в `state`, `current_stage`, `status_history`, `progress` и `tool_label`.
- [x] Итоговый результат живёт в отдельном финальном `assistant-message`, а панель держит `result_message_id`.
- [x] Старый `Action Function` путь не является частью целевой архитектуры `deep-job`.
- [x] Пока `deep-job` активен, интерфейс должен показывать процесс выполнения, а не разговорную реплику модели в будущем времени.
- [x] Пока `deep-job` активен, обычный новый turn не должен исполняться параллельно; он либо блокируется, либо уходит в очередь.

## 10. Smoke-критерии готовности

- [ ] `deep-job` создаёт постоянную панель внутри assistant-message.
- [ ] Панель показывает общий класс `Инструмент долгого выполнения` и отдельно имя конкретного инструмента.
- [ ] Панель не исчезает после следующих сообщений.
- [x] Панель переживает `reload`.
- [x] Главный `Stop` отменяет реальную активную задачу.
- [x] `result_message_id` продолжает корректно фиксироваться.
- [x] Дублирующий terminal result не появляется.
- [ ] Во время активного `deep-job` пользователь видит именно состояние процесса, а не разговорное обещание будущего ответа.
- [ ] Во время активного `deep-job` обычный новый turn не исполняется параллельно без очереди.
- [ ] Панель не зависит от сырых callback-событий `LangGraph` или `LangChain`; для всех long-running инструментов используется единый нормализованный execution-контракт.
- [ ] Если deep-route сформировал отчёт, итоговое сообщение показывает `Скачать отчёт`.
- [ ] Ссылка `Скачать отчёт` в `run_native`-режиме скачивает корректный `pdf`.
- [ ] Ссылка `Скачать отчёт` в контейнерном `Open WebUI` тоже скачивает корректный `pdf`.
- [ ] UI не использует прямой filesystem path для скачивания отчёта; скачивание идёт через backend/proxy-маршрут.
- [x] `tool_jobs` остаётся единственным источником истины.
- [x] Acceptance не зависит от старого `Action Function` пути.
- [ ] Acceptance проходит без `legacy_patch`.

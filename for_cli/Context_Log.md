## [2026-01-06] - Рефакторинг в Middleware-агента

### 1. Создание структуры Workflows
- **Что:** Создана папка `backend/orchestrator/workflows/` с файлами `compare.py` и `equipment.py`.
- **Для чего:** Перенос сложной логики (LangGraph) из монолита `claude_expertV3.py` в микросервисную архитектуру. Это разделяет "мозги" и "тело".

### 2. Рефакторинг Agent API (Оркестратор)
- **Что:** `agent_api.py` переписан. Теперь это диспетчер, который выбирает нужный граф в зависимости от задачи. Добавлен эндпоинт `/v1/chat/completions`.
- **Для чего:** Поддержка **Open WebUI** (OpenAI-совместимость) и устранение "галлюцинаций" ReAct-цикла за счет жестких сценариев LangGraph.

### 3. Интеграция с UMS
- **Что:** Воркфлоу теперь используют `ums_client` для инференса.
- **Для чего:** Разгрузка памяти API-сервера. Модели теперь работают в изолированных процессах `llama-server`.

### 4. Улучшение Document Server (Pagination)
- **Что:** В `mcp_document_server.py` добавлен эндпоинт `/load_pages`.
- **Для чего:** Позволяет оркестратору читать документы постранично. Это фундаментальное требование для реализации стратегии Map-Reduce при анализе больших смет (снятие лимита контекста LLM).

### 5. Реализация Map-Reduce в Workflow Equipment
- **Что:** Узел `extract_data_map_node` теперь работает итеративно. Он запрашивает список страниц и обрабатывает их по одной через UMS.
- **Для чего:** Позволяет обрабатывать сметы на 50+ страниц. Каждая страница анализируется изолированно, результаты агрегируются в единый список объектов JSON.

### 6. Оптимизация Legal Server (Batch Matching)
- **Что:** В `mcp_legal_server.py` реализован эндпоинт `/match_batches`. В воркфлоу `compare.py` внедрено использование этого эндпоинта.
- **Для чего:** Устранение проблемы "N+1 запросов". Сравнение целых документов происходит за один проход через эмбеддер.

### 7. Интеграция с Open WebUI (Docker)
- **Что:** Развернут Open WebUI в Docker. Настроена общая папка (Bind Mount) `backend/open_webui_uploads`.
- **Для чего:** Создание профессионального интерфейса. Общая папка позволяет агенту (на хосте) мгновенно видеть файлы, загруженные пользователем в браузер (в контейнере).

### 8. Исправление инференса эмбеддингов (ST Server)
- **Что:** Создан `st_server.py` для SentenceTransformers. UMS теперь запускает его вместо `llama-server` для модели LaBSE. В `legal_server` добавлена разбивка на мини-батчи по 32 чанка.
- **Для чего:** Решение ошибки `ctx_size` и падений UMS. `SentenceTransformers` корректно обрабатывает длинные тексты и работает стабильнее для задач эмбеддинга.

### 9. Режим свободного общения и детальные отчеты
- **Что:** В `agent_api.py` добавлен "Chat Mode" (ответ через Qwen, если нет файлов). В воркфлоу `compare` и `equipment` добавлена генерация подробных Markdown отчетов с сохранением в файл.
- **Для чего:** Агент стал полноценным ассистентом. Результаты работы теперь сохраняются на диск в виде готовых документов, как это было в исходном монолите.
- **Результат:** README.md полностью переписан под актуальную архитектуру. Добавлены схемы взаимодействия и инструкции по запуску Docker с маппингом томов.

### 11. Анализ статьи на Habr (LangGraph + MCP)
- **Что:** Изучена статья по созданию агентов (https://habr.com/ru/companies/amvera/articles/949376/).
- **Вывод:** Наша текущая архитектура (LangGraph + MCP + UMS) полностью соответствует современным best practices.
- **План на будущее:** Внедрить декораторы @tool и Pydantic для более строгой типизации инструментов в воркфлоу.

# Отчет: Статус и стратегия развития ИИ-агента (Agent Navigator Pro)

**Дата:** 06.01.2026
**Статус:** Переход от прототипа к отказоустойчивой системе.

---

## I. Текущие достижения

1.  **Функциональное ядро:**
    *   Реализован сценарий **сравнения юридических документов** (поиск смысловых изменений, а не просто текстовых различий).
    *   Реализован сценарий **проверки спецификаций оборудования** (ТЗ vs Смета) с использованием Map-Reduce для больших документов.
2.  **Архитектура:**
    *   Внедрен **LangGraph**: Это позволяет жестко контролировать логику рассуждений агента, избегать зацикливаний и делать поведение предсказуемым.
    *   **Локальный инференс**: Система полностью автономна (llama-cpp), данные не покидают периметр компании.

## II. Основные вызовы и решения

| Проблема | Диагноз | Решение |
| :--- | :--- | :--- |
| **Галлюцинации** | Модели иногда искажают цифры в сложных таблицах. | 1. Валидация JSON через Pydantic.<br>2. Тонкая настройка `temperature` (0.1) и `repetition_penalty`.<br>3. Few-shot промптинг (примеры в контексте). |
| **Ресурсы (VRAM)** | Конфликт памяти между LLM (текст) и VL (зрение). | **Unified Model Server (UMS):** Динамическая выгрузка/загрузка моделей. Агент сам освобождает память от OCR-модели перед запуском аналитической LLM. |
| **Интерфейс** | Консоль неудобна для пользователей, свой UI писать долго. | Интеграция с **Open WebUI**. Это готовое решение уровня Enterprise для локальных сетей. |

## III. Технический план действий (Roadmap)

### Этап 1: Стабилизация ядра (Текущий приоритет)
*   [x] Внедрение LangGraph для оркестрации.
*   [ ] **Умный выбор OCR:** Автоматическое переключение между PaddleOCR (быстро/CPU) и Qwen-VL (точно/GPU) в зависимости от сложности страницы.
*   [ ] **Визуализация логики:** Генерация наглядных графов работы агента для отладки и демонстрации.

### Этап 2: Адаптация инфраструктуры
*   **Гибридный режим:**
    *   *Слабые машины:* Использование квантованных моделей (Q4_K_M) и PaddleOCR.
    *   *Серверы с GPU:* Использование vLLM/llama-server для параллельной обработки запросов.
*   **Middleware API:** Обертывание логики агента в API, совместимый с OpenAI, для подключения к любым внешним интерфейсам.

### Этап 3: Внедрение UI
*   Развертывание **Open WebUI**.
*   Подключение агента как "Модели" внутри интерфейса.
*   Настройка RAG (поиск по базе знаний) средствами Open WebUI.

---

## IV. Рекомендации по стеку

1.  **Оркестратор:** LangGraph (Python). Лучший контроль состояний.
2.  **OCR:** Гибрид. PaddleOCR для простых сканов, Qwen-VL для рукописного текста и сложных таблиц.
3.  **UI:** Open WebUI. Сэкономит 3-4 месяца разработки собственного фронтенда.

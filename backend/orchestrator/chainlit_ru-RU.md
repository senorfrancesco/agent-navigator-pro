# Agent Navigator Pro

Агентный интерфейс для анализа документов, RAG-поиска, сравнения юридических материалов и проверки соответствия ТЗ/КП.

## Целевой UX-сценарий (Chainlit)

1. Пользователь открывает **Список чатов** в боковой панели.
2. Выбирает нужный тред из истории.
3. Выбранный тред становится **активным чатом** (дальнейшие сообщения идут именно в него).
4. После переключения отображается явный статус восстановления:
   - сколько сообщений восстановлено;
   - сколько документов найдено;
   - готов ли RAG-индекс.

Это нужно, чтобы пользователь и поддержка всегда понимали, в каком контексте сейчас работает ассистент.

## Что доступно

- анализ одного документа;
- сравнение двух документов;
- ответы по содержимому загруженных файлов;
- анализ оборудования и отчёты по соответствию.

## Как работает переключение между чатами

- История чатов хранится в persistence-слое Chainlit (SQLAlchemy data layer).
- При выборе треда срабатывает `@cl.on_chat_resume` в `chainlit_app.py`.
- В обработчике:
  - восстанавливается история сообщений;
  - извлекается список ранее загруженных файлов;
  - при наличии файлов выполняется повторная загрузка текста и переиндексация RAG;
  - пользователю отправляется единое системное сообщение со статусом восстановления.
- Если документы не найдены или текст не удалось поднять, чат всё равно открывается, но статус явно показывает, что RAG не готов.

## Рекомендации

- для вопросов по документам лучше держать один набор файлов в рамках одного чата;
- если после resume RAG «не готов», перезагрузите документы в активный чат;
- ответы LLM могут ошибаться, критичные выводы проверяйте по исходному документу.
